# 第 4 章 传输协议基础

## 4.1 UDP 协议

UDP 是实时视频回传中最常用的基础协议之一。其特点是无连接、开销小、时延低，但不提供可靠传输、顺序保证和拥塞控制。

在聚合路由器到聚合服务器的传输过程中，可基于 UDP 实现自定义包头、序号、时间戳、链路标识、丢包检测、重排缓存和 FEC/ARQ 等机制。

## 4.2 TCP 协议

TCP 提供可靠、有序、面向连接的传输能力，具备重传和拥塞控制机制。但对于实时视频，TCP 的队头阻塞和重传等待可能导致时延增大。

TCP 可用于控制信令、管理通道、状态上报等非强实时数据，不宜直接作为低时延视频聚合回传的唯一传输方式。

## 4.3 RTP/RTCP

RTP 是实时音视频传输协议，常与 UDP 配合使用。RTP 包头中的 sequence number、timestamp、payload type 和 SSRC 对视频流排序、同步和统计具有参考价值。

RTCP 可用于接收质量反馈，包括丢包、抖动和往返时延等信息。自定义聚合协议可以参考 RTP/RTCP 的设计思想。

## 4.4 QUIC 基础

QUIC 基于 UDP 实现，内置 TLS 加密、多路复用、拥塞控制和连接迁移能力。对于移动网络场景，QUIC 的连接迁移机制具有一定价值。

若后续研究 Multipath QUIC，可进一步探索其在多链路视频回传中的适用性。对于低时延场景，可关注 QUIC Datagram。

## 4.5 SRT 基础

SRT 是面向不稳定网络的视频传输协议，支持 ARQ 重传、延迟缓冲、丢包恢复和加密传输，常用于直播和远程视频回传。

在实验模型中，SRT 可作为单链路可靠视频传输对比方案，也可作为设计自定义聚合传输机制时的重要参考。

## 4.6 MPTCP 基础

MPTCP 是 TCP 的多路径扩展，可通过多个子流同时传输数据。其优点是对应用透明、可靠性较好，但仍然继承 TCP 的有序交付和队头阻塞问题。

对于实时视频回传，MPTCP 可作为多链路传输的对比技术，但不一定是最低时延场景下的最优选择。

## 4.7 MPUDP 基础

MPUDP 通常不是单一标准协议，而是指基于 UDP 构建的多路径传输机制。其典型做法是在 UDP 之上自定义聚合协议头，并由聚合路由器根据链路状态将视频数据分发到多条链路。

MPUDP 的优势是灵活、低时延、可控制性强，适合实现链路质量感知、包级调度、乱序重排、FEC、NACK、关键帧冗余和实时丢弃策略。

其主要不足是可靠性、拥塞控制、乱序处理和安全机制需要自行设计，工程复杂度高于直接使用成熟协议。

## 4.8 SCTP 基础

SCTP 是一种独立传输层协议，支持多流、多宿主、可靠传输和消息边界保持。与 TCP 相比，SCTP 的多流能力可以降低部分队头阻塞影响，多宿主能力可以用于链路故障切换。

但 SCTP 在公网环境中的部署普及度不如 TCP/UDP，NAT 和防火墙穿透也更复杂。在本课题中，SCTP 更适合作为控制信令、链路状态上报和设备管理通道，而不是视频数据主通道。

## 4.9 MPTCP、MPUDP、SCTP 用法对比

| 协议 | 核心定位 | 优点 | 局限 | 推荐用途 |
|---|---|---|---|---|
| MPTCP | 可靠多路径 TCP | 对应用透明、内核支持、可靠传输、链路容灾 | 队头阻塞、重传等待、调度不易自定义 | 对比方案、文件/日志回传、非强实时数据 |
| MPUDP | 自定义低时延多路径 UDP | 灵活、低时延、适合包级调度和视频感知传输 | 需要自行处理可靠性、拥塞和乱序 | 视频数据主通道、核心实验方案 |
| SCTP | 多流多宿主可靠传输 | 消息边界、多流、多宿主、适合信令 | 公网部署受限、视频生态较弱 | 控制信令、状态上报、设备管理 |

面向无人机、无人车实时图像回传，推荐采用如下分工：

```text
数据面：MPUDP
控制面：TCP / QUIC / SCTP
对比方案：MPTCP
```
