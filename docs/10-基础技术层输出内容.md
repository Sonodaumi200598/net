# 第 10 章 基础技术层输出内容

## 10.1 对上层提供的能力

- 可用链路列表。
- 每条链路的接口名、IP 地址、网关和在线状态。
- 基础链路质量参数，包括 RTT、丢包率、抖动和吞吐量。
- 按指定链路发送数据的接口能力。
- 从多条链路接收数据的接口能力。
- 基础安全通道和身份认证能力。
- 视频流输入输出接口。

## 10.2 基础技术层约束

- 单个数据包大小应尽量小于路径 MTU，避免 IP 分片。
- 多网卡路由必须可控，避免数据包走错出口链路。
- 链路状态必须可观测，便于上层调度算法及时调整。
- UDP 不提供可靠传输，丢包、乱序和重复包需要上层处理。
- TCP 的可靠性可能引入额外等待和队头阻塞。
- 实时视频不适合无限等待重传，需要设置超时和丢弃策略。

## 10.3 基础技术层评价指标

- 链路连通率。
- 基础 RTT。
- 基础丢包率。
- 基础抖动。
- 单链路吞吐量。
- 多链路总可用带宽。
- 网卡切换检测时间。
- 链路中断检测时间。
- CPU、内存和网卡资源占用。

## 10.4 链路质量评分公式

将测量结果转换为统一链路质量分数。对路径 $i$ 使用以下公式：

$$
Q_i = w_B\hat{B}_i + w_D\hat{D}_i + w_J\hat{J}_i + w_R R_i^{deadline}
$$

其中：

| 符号 | 含义 | 取值方向 |
|---|---|---|
| $Q_i$ | 路径 $i$ 的综合质量分数 | 越大越好，范围为 0～1 |
| $\hat{B}_i$ | 安全可用带宽的归一化质量分 | 带宽越大，分数越高 |
| $\hat{D}_i$ | 时延转换后的归一化质量分 | 时延越小，分数越高 |
| $\hat{J}_i$ | 抖动转换后的归一化质量分 | 抖动越小，分数越高 |
| $R_i^{deadline}$ | 在 deadline 前成功到达的数据包比例 | 按时到达比例越高，分数越高 |
| $w_B,w_D,w_J,w_R$ | 四项指标的权重 | 非负且总和为 1 |

该公式用于评分和分析，不能替代原始测量。链路是否在线、认证是否通过、路径 MTU 是否有效等仍属于前置条件；不可达或未认证链路即使历史 $Q_i$ 较高，也不能参与调度。


## 10.5 权重与链路等级

面向实时视频，实验初始权重固定为：

```text
w_B = 0.30    安全可用带宽
w_D = 0.25    时延质量
w_J = 0.15    抖动质量
w_R = 0.30    deadline 前到达率
```

权重总和为 1。该设置同时重视承载能力和按时交付，并避免只选择高带宽但高时延的链路。后续实验可以在保证权重和为 1 的条件下进行消融和敏感性分析。

| 评分范围 | 链路等级 | 调度动作 |
|---|---|---|
| $0.80 \le Q_i \le 1.00$ | 优秀 | 承担关键帧和较高发送权重 |
| $0.60 \le Q_i < 0.80$ | 良好 | 正常参与多路径传输 |
| $0.40 \le Q_i < 0.60$ | 降级 | 降低权重，优先发送普通数据或 FEC |
| $0 < Q_i < 0.40$ | 较差 | 仅保活、试探或兜底使用 |
| $Q_i=0$ | 不可用 | 停止业务调度并等待恢复探测 |

等级切换需要迟滞机制，例如连续 3 个统计窗口满足条件后再切换，防止 5G、Wi-Fi 短时波动造成调度权重频繁振荡。链路不可达、连续认证失败或预计到达时间超过当前切片 deadline 时采用硬门限，直接停止为该切片选择该路径。

## 10.6 评分驱动的多路径调度

对仍能在 deadline 前到达的可用路径，调度权重可按以下方式计算：

$$
P_i=\frac{Q_i}{\sum_{j\in A}Q_j}
$$

其中 $A$ 是当前可用且满足切片 deadline 的路径集合，$P_i$ 是路径 $i$ 的初始数据比例。由于 $Q_i$ 已包含带宽质量项，计算比例时不再额外乘以带宽，避免重复放大带宽影响。分配到路径 $i$ 的实际速率不得超过 $B_i^{safe}$，超出部分按剩余路径的质量分重新分配。最终发送还必须服从第 5 章规定的 `pacing_rate` 和 `cwnd`，链路分数不能绕过拥塞控制器直接增加发送量。

调度器按照以下顺序决策：

1. 根据在线状态、身份认证、MTU 和预计到达时间过滤不可用路径。
2. 使用最近窗口的 $Q_i$ 和 $B_i^{safe}$ 计算基础分配比例。
3. I 帧和重要参考帧优先选择高 $Q_i$、低时延路径，必要时跨路径发送受控冗余。
4. 普通 P 帧按 $P_i$ 分配，FEC 可发送到与原始片故障相关性较低的另一条路径。
5. 若所有路径均无法满足 deadline，则不发送已经过期的低优先级切片，并触发码率降低或关键帧恢复策略。

## 10.7 链路质量与视频 QoE 分析

$Q_i$ 表示网络路径质量，不等同于最终视频 QoE。服务器需要把每个评分窗口与同一时间段的视频指标关联，分析链路变化是否真正影响观看质量：

| 链路评分变化 | 可能的网络现象 | 需要观察的视频 QoE |
|---|---|---|
| $\hat{B}_i$ 下降 | 安全发送容量不足、编码输入超过链路能力 | 码率下降、分辨率变化、主动丢帧 |
| $\hat{D}_i$ 下降 | RTT 或排队时延上升 | 端到端延迟、过期包和交互响应变差 |
| $\hat{J}_i$ 下降 | 到达时间波动、乱序增加 | 重排等待、卡顿和缓冲占用上升 |
| $R_i^{deadline}$ 下降 | 丢包或大量数据迟到 | 花屏、FEC/NACK 增加、关键帧恢复 |
| $Q_i$ 持续下降 | 链路整体退化 | 可解码帧率、PSNR、SSIM、VMAF 下降 |

每条记录至少关联 `time、session_id、path_id、Q_i、四个分项、调度权重、发送字节数、FEC/NACK 结果`。视频侧同步记录卡顿次数、关键帧恢复时间、连续可解码帧率和 VMAF 等指标。通过时间序列对齐，可以比较质量感知调度与轮询、固定权重调度的端到端时延、恢复率和 QoE，而不是只比较吞吐量。

链路评分计算路线如下：

```text
MPUDP/QUIC 反馈与主动探测
          │
          ▼
获得 B、RTT/时延、Jitter、按时到达包数
          │
          ▼
异常值处理 → 1 秒窗口聚合 → EWMA 平滑 → 归一化
          │
          ▼
Q_i = 0.30B̂_i + 0.25D̂_i + 0.15Ĵ_i + 0.30R_i^deadline
          │
          ├── 写入 TimescaleDB，用于历史链路质量与 QoE 分析
          └── 输入 Multipath Scheduler，更新链路选择和调度权重
```
